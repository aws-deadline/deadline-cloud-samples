# Add HuggingFace LLM Fine-Tuning (LoRA/QLoRA) job bundle

## Summary

Adds a new job bundle for parameter-efficient fine-tuning of HuggingFace causal
language models (LLMs) on AWS Deadline Cloud. Supports LoRA and QLoRA
(4-bit-quantized) fine-tuning using `transformers`, `peft`, and `bitsandbytes`.

This complements the existing image-model LoRA bundle (`flux2_klein_lora`) and
extends the samples to cover the text/LLM side of generative AI fine-tuning.

## How it works

1. User uploads a JSONL dataset (`{instruction, output}` per line) to S3
2. Submits the bundle via `deadline bundle submit` (CLI) or `gui-submit` (form)
3. Worker installs PyTorch + HuggingFace stack, downloads the dataset and base model,
   runs QLoRA fine-tuning on a single GPU
4. The trained LoRA adapter (~50-200 MB) is uploaded back via job attachments
5. User downloads with `deadline job download-output` and uses with `peft.PeftModel`

## Supported models

Any HuggingFace causal LM with standard Llama-style attention/FFN module names,
including:

- Qwen (2, 2.5, 3)
- Llama (2, 3, 3.1, 3.2)
- Mistral / Mixtral
- Gemma (2)
- Phi (3, 3.5)
- DeepSeek

## Testing

Successfully tested end-to-end on:

- **Smoke test**: Qwen/Qwen2.5-0.5B, 10 samples, 1 epoch — pipeline validation, ~30s on NVIDIA L4
- **Fact memorization (winning config, now the default)**: Qwen/Qwen2.5-**7B**,
  118 samples (Saffron Stack thematic subfolders), 10 epochs, LoraRank=32,
  LoraAlpha=64, LearningRate=1e-4, PerDeviceBatchSize=1, GradAccumSteps=4.
  Loss 2.5 → 0.44 in ~10 min on NVIDIA L4. Adapter correctly recalls **8/8**
  invented facts on the built-in test suite (`RunTests=yes`), including
  bio-swap-prone questions like "Who founded Saffron Stack?" that smaller
  models get wrong.
- **Multi-file loading**: Verified recursive `.jsonl` glob on both flat
  (single folder) and nested (subfolder) layouts.
- **Local + S3 dataset modes**: Both `DatasetPath` (auto-uploaded via job
  attachments) and `DatasetS3Uri` (direct fetch from S3, supports both single
  file and prefix) tested end-to-end.

## Fleet requirements

- Linux, x86_64
- 1 NVIDIA GPU (Ampere or newer recommended for bf16)
- 16 GB+ VRAM (24 GB+ recommended for 7B+ models)
- 32 GB+ system RAM

Validated on a service-managed EC2 fleet with NVIDIA L4 GPUs.

## Notes

- Dataset format matches popular instruction datasets (Alpaca, Dolly, etc.) so
  users can swap in public datasets via `InstructionColumn` / `ResponseColumn`
  parameters.
- Dataset loaded directly from S3 via boto3 (the queue role needs `s3:GetObject`
  on the dataset prefix — README documents the IAM setup).
- HF model cache is persisted to `/mnt/persistent/hf_cache` so subsequent jobs
  on the same worker reuse downloaded weights.
- For gated models (Llama, Mistral, Gemma), the bundle accepts a HuggingFace
  token via the `HuggingFaceToken` parameter. README recommends setting it as
  a queue env var in production rather than passing as a job parameter.
